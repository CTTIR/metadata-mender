# Metadata Mender maintenance audit — 2026-10-30

Scope: dependable private local use of the selected-item metadata reconciler.
Baseline: `9db830b` (0.6.0), with a clean working tree before maintenance.
Candidate: 0.6.1 on `maintenance/zotero10-safety-20261030`. No publication,
installation in the normal profile, or real-library modification was performed.

## Acceptance criteria and roadmap

1. **Metadata integrity:** preserve reviewed fields by default; require returned
   identifier identity; reject ambiguous title matches; protect edited, deleted,
   read-only and concurrently changed items. Complete in source and regression tests.
2. **Operational reliability:** bound requests and retries, sanitize error messages,
   stop pending writes on cancellation, and reload failed staged changes. Complete
   in source and regression tests. A save already underway may finish on cancellation.
3. **Dependable packaging:** preserve older artifacts, verify every packaged runtime
   byte, keep manifest/update versions consistent, and reproduce identical archives.
   Complete locally; remote CI has not been run for these uncommitted changes.
4. **Desktop qualification:** exercise lifecycle, preferences, menu entry, real
   Zotero item saves, cancellation and disabling in an isolated synthetic profile.
   Coordinated separately; pending evidence must not be inferred from Node stubs.

Deferred: a per-field review/preview UI, institution/consortium author parsing,
multilingual metadata policies, live contract fixtures for all eight providers,
and wider Zotero versions. These require separate evidence and are not implied by
the compatibility declaration.

## Confirmed findings and repairs

| Severity | Evidence at baseline | User impact and repair |
|---|---|---|
| High | `_setDefaultPrefs` migrated `fill` to `overwrite`; initials and title search defaulted on | Existing metadata could change without an explicit new choice. Removed forced migration; conservative new defaults and preserved saved settings. |
| High | `_tryTitleFallback` accepted title similarity ≥ 0.7 alone | Wrong DOI adoption. Opt-in now requires a unique candidate with title, first-author, year, type and publication agreement. |
| High | `_fetchAllSources` trusted records without returned DOI/PMID identity | Wrong metadata could be merged. Require matching returned identifiers, including PubMed's returned UID; reject title/author conflicts. |
| High | Input extraction accepted conflicting native/Extra identifiers and CRAN host substrings inside unrelated URLs | A different identifier could be silently selected. Refuse ambiguous or malformed local identifiers and require an actual CRAN URL shape. |
| High | `reconcileItem` had no pending-edit, permission, deletion or post-network snapshot guards | Concurrent work could be overwritten. Guard before lookup and immediately before mutation; reload staged changes on failure. |
| High | `_augmentExtra` assumed unsupported `getField` throws; Zotero returns an empty string | Later `setField` could throw after earlier mutations. Use schema validity and retain identifiers in Extra when no native field exists. |
| High | `_get` used unsupported `errorOnStatus:false`; observed Zotero HTTP defaults allow up to one hour of native retries | 404 handling and bounded retries did not execute as intended. Use `successCodes:false`, `errorDelayMax:0`, `noRetryOnThrottle:true`; test the actual option contract. |
| Medium | HTTP errors included full request URLs with query credentials | Credential exposure through plugin error logging/UI. Report host/status only; use OpenAlex header authentication and refuse redirects. Zotero native debug logs can still include lookup text/email. |
| Medium | Extra deduplication and broad mended-tag removal could erase user data | Preserve conflicting stable identifiers in fill mode, manual tags and unrelated Extra lines. Unexpected setter errors now roll back the item. |
| Medium | PubMed author parser treated the first word as the full surname | Compound surnames were corrupted. Split final initials from the complete preceding surname. |
| Medium | OpenAlex citedness was labelled Impact Factor | Misleading analytical label. Write `OpenAlex 2yr mean citedness`; retain previous/manual Impact Factor lines. |
| Medium | Manifest stopped at Zotero 9; build deleted older XPI files before packaging | Installed Zotero 10 rejected the plugin; builds could erase prior artifacts. Declare 9.0–10.0.x and replace packaging with deterministic, staged verification. |

## Observed validation

- Baseline: 22 helper tests passed, despite the above behavioral defects.
- Candidate: `node --test tests/*.test.js` — **40 passed, 0 failed** on Node
  26.12.0 and Python 3.9.6. Tests cover realistic reconciliation failure paths,
  identifier/author/title conflicts, Extra/manual-tag preservation, stale edits,
  cancellation, mutation/save rollback, HTTP behavior, and artifact reproducibility.
- `node --check bootstrap.js`, `node --check content/metadata-mender.js`, and
  `git diff --check` passed.
- `./build.sh` and `python3 tools/build.py --check metadata-mender-0.6.1.xpi`
  passed. Eight runtime files match source; repeated builds were byte-identical;
  a prior-artifact sentinel survived. The artifact's SHA-256 is printed by the
  checker so subsequent source changes cannot silently retain stale evidence.
- Installed official Zotero application source (10.0.5, then 10.0.6 after its
  update) was inspected for `ItemFields`, item setters/reload, and HTTP options.
  This source inspection is not a substitute for live desktop qualification.
- The guide referenced three missing screenshots; removed those broken links.
  Quarto is unavailable locally, so documentation rendering remains unverified.
- No external provider responses were fetched using private library data. Node
  tests use synthetic inputs. No remote CI, release, or Zenodo deposit was observed.

## Compatibility and first use

The manifest follows Zotero's [tested-minor compatibility guidance](https://www.zotero.org/support/dev/zotero_7_for_developers)
with `strict_max_version: 10.0.*`. The [JavaScript API guide](https://www.zotero.org/support/dev/client_coding/javascript_api)
describes transaction-backed item saves; the installed official source supplied
the detailed field and HTTP contracts checked here.

With Python 3.9+ and Node.js 22+, run from the repository root:

```sh
node --test tests/*.test.js
./build.sh
python3 tools/build.py --check metadata-mender-0.6.1.xpi
```

Install the resulting XPI via Tools → Plugins → Install Plugin From File in a
separate test profile first. Use a disposable regular item with a known DOI,
select Fill empty fields only, then right-click → Mend metadata. Inspect the
updated fields and Extra. New installations retain full names and disable title
search. An existing user's saved overwrite/title preferences are retained and
should be reviewed before use. Credentials reside in Zotero preferences; chosen
identifiers and optional title queries are transmitted to configured services.

Run Mender before Zotero Library Workbench extraction/audit. Close Zotero for
Workbench operations, retain backups, and regenerate correction plans after any
metadata changes. Competing metadata writers should not run concurrently.

`CITATION.cff` and the DOI retain the existing archived 0.1.0 provenance; they do
not establish an archived release of this local 0.6.1 candidate. Publication and
normal-profile installation remain separate actions after qualification.
